# Архитектурное видение (На будущее): Mattermost Mock API

Этот документ фиксирует альтернативный, более продвинутый подход к интеграции OpenClaw и Mattermost, который обсуждался как замена текущему Gateway WebSocket (webchat) роутингу.

## 🔴 Текущая архитектура (Gateway WS)

Сейчас `ws_router` подключается к OpenClaw через универсальный Gateway API (как клиент типа `webchat`).
* **Проблема:** Агент OpenClaw не знает, что он общается через Mattermost. Он ограничен базовой схемой `webchat`, которая плохо справляется с вложениями (LLM отказывается отдавать `mediaUrls` или прячет пути).
* **Наш текущий Workaround:** Регулярные выражения (Regex) поверх текста + (в планах) FS Watcher за директорией `/workspace/downloads`.

## 🟢 Альтернативная архитектура: Mattermost Mock API

Вместо того чтобы `ws_router` был *клиентом* для OpenClaw, мы превращаем `ws_router` в **прокси-сервер, эмулирующий Mattermost API**.

### Как это работает:
1. Инстанс OpenClaw настраивается на использование своего встроенного нативного `mattermost` плагина.
2. В конфиге OpenClaw:
   ```json
   "mattermost": {
     "baseUrl": "http://ws_router:8060/api/v4", 
     "token": "fake-router-token"
   }
   ```
3. OpenClaw думает, что `ws_router` — это настоящий сервер Mattermost. Он использует свои лучшие, нативные системные промпты для работы с Mattermost (где идеально поддерживаются треды, вложения, Markdown-форматирование).
4. `ws_router` принимает HTTP REST-запросы от OpenClaw (например, загрузка файлов `POST /api/v4/files`) и проксирует их в реальный Mattermost.
5. События от реального пользователя в Mattermost перехватываются `ws_router` и отправляются в OpenClaw через эмулированный WebSocket-туннель `/api/v4/websocket`.

### Плюсы (Нативность)
* **Агент работает "как дома":** Интеграция с файлами, картинками и сложным форматированием работает "из коробки", так как ядро OpenClaw уже умеет идеально работать с Mattermost.
* **Никаких костылей:** Не нужны парсеры текста, регулярные выражения или FS Watchers. Отправка файлов происходит стандартным HTTP POST-запросом от агента.
* **100% совместимость:** Полное соответствие поведения агента ожиданиям пользователей.

### Подводные камни (Трудозатраты)
Переход на эту архитектуру требует реализации "мини-Mattermost" внутри `ws_router`:
1. **Эмуляция WebSocket:** Потребуется реализовать протокол Mattermost (ping/pong, hello, sequence numbers), чтобы агент мог слушать события.
2. **Эмуляция Startup API:** Плагин Mattermost при старте запрашивает `/api/v4/users/me`, `/api/v4/config` и т.д. Эти эндпоинты придется "заглушить" (mock), отдавая валидные JSON-ответы.
3. **Маршрутизация:** Перевод входящих файлов из OpenClaw в реальный Mattermost.

### Итог
Если текущий подход (FS Watcher + Regex) упрется в ограничения или агент начнет сильно галлюцинировать при работе с файлами, **Mattermost Mock API — это ультимативное архитектурное решение**, которое переводит ответственность за форматирование и доставку файлов обратно на плечи нативного ядра OpenClaw.
