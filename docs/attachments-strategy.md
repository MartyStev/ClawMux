# Стратегии обработки вложений (Attachments)

В данном документе описаны варианты реализации поддержки вложений (изображений, документов, таблиц) при интеграции Mattermost и OpenClaw через WS Router.

## Проблема
Пользователи Mattermost часто отправляют файлы. OpenClaw (LLM агент) должен иметь возможность получить доступ к содержимому этих файлов для анализа. Прямые ссылки на файлы в Mattermost защищены авторизацией и недоступны инстансам OpenClaw напрямую.

---

## Вариант 1: Изолированные локальные тома (Shared Volumes)

### Описание
Роутер скачивает файл из Mattermost и сохраняет его в локальную папку `workspace` конкретного инстанса пользователя.

### Реализация
1. Роутер (`ws_router`) монтирует корень всех конфигураций: `/root/openclaw/user-configs:/configs`.
2. При получении файла роутер скачивает его через Mattermost API.
3. Файл сохраняется по пути `/configs/<UUID>/workspace/downloads/<filename>`.
4. В сообщение для OpenClaw добавляется мета-информация о локальном пути к файлу: `/home/node/.openclaw/workspace/downloads/<filename>`.

### Безопасность
* **Высокая.** Каждый инстанс OpenClaw видит только свой `workspace` благодаря Docker-монтированию. Инстанс А физически не может получить доступ к файлам инстанса Б.
* Роутер имеет доступ ко всем папкам, но он является доверенным системным компонентом.

### Плюсы и минусы
* **[+]** Агент может читать файлы мгновенно (через bash/python).
* **[+]** Нет лимитов на размер файлов в WebSocket.
* **[-]** Требует настройки прав доступа (UID/GID) на файловой системе хоста.

---

## Вариант 2: HTTP-прокси внутри WS Router

### Описание
Роутер выступает в роли шлюза для скачивания файлов.

### Реализация
1. В `ws_router` создается эндпоинт `GET /api/v1/files/{file_id}/{token}`.
2. Роутер при получении файла генерирует уникальный одноразовый токен.
3. OpenClaw получает ссылку: `http://ws_router:8060/api/v1/files/abc123xyz`.
4. Инстанс OpenClaw использует инструмент (например, `curl` или `wget`), чтобы скачать файл по этой ссылке. Роутер проксирует запрос в Mattermost с использованием Bot Token.

### Плюсы и минусы
* **[+]** Не требует монтирования общих папок.
* **[+]** Универсально для облачных сред.
* **[-]** Дополнительный шаг для агента (нужно сначала скачать файл, прежде чем прочитать).

---

## Вариант 3: Объектное хранилище (S3 / MinIO)

### Описание
Использование внешнего или локального S3-совместимого хранилища.

### Реализация
1. Поднимается контейнер **MinIO** или используется внешний S3 (Yandex Cloud, AWS).
2. Роутер скачивает файл из Mattermost и загружает в S3.
3. Роутер генерирует **Pre-signed URL** (безопасную временную ссылку).
4. OpenClaw скачивает файл по этой ссылке своим инструментом.

### Плюсы и минусы
* **[+]** Максимальная масштабируемость и чистота архитектуры.
* **[+]** Возможность хранения архива файлов вне сервера приложений.
* **[-]** Требует дополнительной инфраструктуры (S3).

---

## Сравнение

| Характеристика | Вариант 1 (Volumes) | Вариант 2 (Proxy) | Вариант 3 (S3) |
| :--- | :--- | :--- | :--- |
| **Сложность внедрения** | Низкая | Средняя | Высокая |
| **Производительность** | Высокая (локально) | Средняя | Средняя |
| **Изоляция данных** | Физическая (Docker) | Программная | Программная (ACL) |
| **Доступ агента** | Прямой (File System) | Через инструмент (Network) | Через инструмент (Network) |

## Резюме
Для текущей архитектуры, где инстансы работают на одном хосте, **Вариант 1** является наиболее эффективным и безопасным при условии правильной настройки Docker-томов. Если планируется переход в облако (Kubernetes), рекомендуется **Вариант 3**.
